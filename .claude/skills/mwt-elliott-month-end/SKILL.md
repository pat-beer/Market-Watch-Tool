# Market Watch Tool — Elliott Wave (สิ้นเดือน)

ใช้เมื่อผู้ใช้ขอ "ทบทวนคลื่น", "นับ Elliott ใหม่", "EW สิ้นเดือน" หรือเมื่อ weekly review แจ้งว่า key level หลุด ตอบเป็นภาษาไทย สั้น ตรงประเด็น

## หลักการ
- ทำเต็มรูปแบบเฉพาะ **สิ้นเดือน** รายสัปดาห์เช็กแค่ว่าราคาปิดหลุด `keyLevel` หรือไม่ (อ่านอย่างเดียว) ถ้าหลุดนับก่อนสิ้นเดือนได้
- Elliott เป็นการตีความ ต้องให้ **นับหลัก + นับรอง** พร้อมระดับที่ทำให้นับหลักเป็นโมฆะ ห้ามตอบแบบฟันธง และห้ามเขียนเหมือนเป็นคำแนะนำซื้อขาย
- ตัวที่นับ: SPY, SMH (DAPP ถอดออกรอบ พ.ย. 2026 เพราะโครงสร้างเป็น corrective และทำ lower low) ก่อนเริ่มให้ถามผู้ใช้ว่าจะเพิ่ม GC=F, BTC-USD, QQQM หรือไม่ (ยังไม่ได้ตัดสินใจ)

## ข้อมูลและความถูกต้อง (สำคัญที่สุด)
- ใช้เฉพาะ `data/series.json` (ราคาปิดรายวัน ~300 วัน เริ่ม ก.ย. 2025 ไม่มี high/low มี `d`, `c`, `m50`, `m100`, `m200`) และ `data/prices.json` ห้ามอ้างราคาจากความจำ ห้ามคัดลอก pivot เดิมจาก analysis.json มาใช้โดยไม่ตรวจ
- **ทุก pivot ต้องตรวจเทียบ series.json**: วันที่ต้องอยู่ในข้อมูลและราคาต้องตรงราคาปิดวันนั้น ถ้าวันที่อยู่นอกช่วง (เช่น pivot ปี 2024 ในรอบเก่า) ให้ระบุว่าตรวจไม่ได้ และนับเฉพาะส่วนที่ตรวจได้ หรือบอกผู้ใช้ว่าต้องเพิ่มช่วงข้อมูลใน `update_prices.py`
- ตรวจสเกลก่อนเขียน: pivot ล่าสุดต้องอยู่ใกล้ `last` ในหน่วยเดียวกัน ถ้าต่างเกิน ~25% โดยไม่มีเหตุผลชัดเจนให้ถือว่าผิดสเกล (รอบ 22 ก.ย. เคยผิด: SMH pivot 5 = 353.7 แต่ราคาจริงวันนั้น 607, DAPP 64.98 แต่จริง 21.72)
- กฎที่ต้องไม่ขัด: คลื่น 2 ไม่ย้อนต่ำกว่าจุดเริ่มคลื่น 1, คลื่น 3 ต้องไม่สั้นที่สุดในสามคลื่นผลัก (1,3,5), คลื่น 4 ไม่ทับพื้นที่ราคาของคลื่น 1 (ยกเว้น diagonal ต้องระบุชัด) ถ้านับตามกฎไม่ได้ ให้บอกว่าโครงสร้างยังไม่ชัด และ **ถอดรายการนั้นออกจาก `waves`** แทนการฝืนนับ (แอปไม่แสดงกล่อง Elliott ถ้าไม่มีรายการ)
- ความไม่แน่นอนจากการใช้ราคาปิดอย่างเดียวและข้อมูล ~14 เดือน ต้องระบุใน note ทุกครั้ง

## ขั้นตอน
1. clone/fetch repo `pat-beer/Market-Watch-Tool` แล้ว `git reset --hard origin/main` อ่าน `waves` ปัจจุบัน และดูว่า `app.js` (`waveBox`) อ่าน field อะไร: `current` (1–5), `alt` (1–5), `keyLevel {price, note}`, `note`, `asof` ส่วน `pivots` ไม่ถูกแสดง (เก็บเป็นบันทึก) ห้ามเปลี่ยนรูปแบบ
2. ตรวจว่า prices.json เป็นข้อมูลหลังตลาดปิดหรือไม่ (`updated` หลัง ~21:00Z) ระบุวันที่ของราคาที่ใช้
3. หา swing pivot จากราคาปิด (zigzag หรือรายสัปดาห์) หาจุดต่ำ/สูงร่วมของตลาด (รอบ พ.ย. 2026: low ร่วมวันที่ 2026-03-30)
4. นับหลักและนับรอง กำหนด `current`/`alt` ตามตัวเลข 1–5 ของแอป
5. กำหนด `keyLevel` = ระดับแรกที่ควรกลับมาทบทวน (ใช้ราคาปิด) ส่วนระดับที่ทำให้นับเป็นโมฆะจริง ๆ (หลัก/รอง) เขียนใน note
6. เขียน note ภาษาไทย: นับหลัก, นับรอง, ระดับ invalidation, ความมั่นใจ (สูง/กลาง/ต่ำ), ข้อจำกัดข้อมูล
7. ตั้ง `asof` เป็นวันที่ของราคาล่าสุดที่ใช้
8. เขียนไฟล์ด้วย splice เฉพาะบล็อก `  "waves": {` ด้วยการนับปีกกา ห้าม `json.dump` ทั้งไฟล์ แล้ว assert ว่าบล็อกอื่น (`daily`, `weekly`, `demo`, `asof`) เหมือนเดิม และ parse JSON ได้
9. รัน `node scripts/test-rules.mjs` ต้องผ่านทั้งหมด
10. ส่งมอบแบบเดียวกับ skill `mwt-weekly-review` (commit → ลอง push → 403 → patch → `git apply --check` ใน worktree → SendUserFile → ให้ผู้ใช้ apply และ push เอง)

## รายงานสุดท้าย (สั้น)
ต่อ ticker: นับหลัก / นับรอง / key level / ราคาตอนนี้เทียบ key level / ความมั่นใจ และตัวที่ถอดออกพร้อมเหตุผล ปิดท้ายว่าเป็นมุมมองเชิงเทคนิค ไม่ใช่คำแนะนำซื้อขาย
